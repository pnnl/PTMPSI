# MM/GBSA Scripts

This directory contains the pipeline used to select, run, and extract Generalized-Born MM/GBSA
binding-energy calculations for the CP12–GAP2/PRK ("dark complex") interface, restricted to the
top-5%-per-ensemble structural-PCA selection (plus the REF control). Calculations are performed
with `gmx_MMPBSA` on trajectories from `<ENSEMBLE>_NAD/postprocess_final/`.

Ligand = 4 CP12 chains. Receptor = GAP2 + PRK (+ NAD cofactors, per the index groups generated by
`make_mmpbsa_index.py`). ΔTOTAL is therefore the binding energy of CP12 to the GAP2·PRK
supercomplex; more negative = stronger binding.

## Pipeline order

1. **`build_mmgbsa_manifest.py`** — Reads each ensemble's ranked PCA-distance-to-REF CSV
   (`suman_pca_structural_only_90pct/pca_distance_to_ref_90pct_ranked.csv`) and the list of
   systems affected by a prior trajectory correction. Computes the top-5%-per-ensemble selection
   (Tier A = HM2/MED4 overlap, Tier B = union), decides per system whether an existing MM/GBSA
   result can be reused or a new run is required, and writes the selection lists and
   `mmgbsa_downselection_manifest.csv` under `mmgbsa_selection/`.
2. **`stage_mmgbsa_inputs.py`** — For each system on the selection lists, creates
   `<postprocess_final>/<sys>/mmgbsa/`, copies in `mmpbsa_template.in` (as `mmpbsa.in`) and
   `make_mmpbsa_index.py`, locates and copies a `topol.top` from one of several fallback source
   trees, symlinks in the custom `amber99sb.ff` force field directory, and symlinks the trajectory/
   structure/topology files from the parent system directory. This is a standalone alternative to
   the inline staging that `run_mmgbsa.sbatch` also performs itself (`prepare_one()`).
3. **`submit_mmgbsa.sh`** — Submits `run_mmgbsa.sbatch` as two SLURM job arrays (HM2 and MED4) over
   the `*_top5pct_ready_for_new_mmgbsa.txt` lists produced in step 1, with `FORCE=1` to overwrite
   any stale results.
4. **`run_mmgbsa.sbatch`** — The production SLURM array driver. Each array task stages a batch of
   systems (`prepare_one()`: copies the mmpbsa.in template and index script, links the force field
   and trajectory inputs, builds `mmpbsa.ndx` via `make_mmpbsa_index.py`) and then runs
   `gmx_MMPBSA` (32 MPI ranks/system) to produce `FINAL_RESULTS_MMPBSA.{dat,csv}` per system.
   Skips systems that already have `FINAL_RESULTS_MMPBSA.csv` unless `FORCE=1`.
5. **`extract_mmgbsa_results.py`** — Parses the ΔTOTAL/ΔVDWAALS/ΔEEL/ΔGSOLV/... block out of every
   selected system's `FINAL_RESULTS_MMPBSA.dat`, restricted to the current `in_top5pct=True` set
   (plus REF unconditionally), and writes per-ensemble and combined per-system energy CSVs plus a
   text summary.
6. **`extract_mmgbsa_decomposition.py`** — Parses the per-residue `DELTAS` block out of each
   selected system's `FINAL_DECOMP_MMPBSA.dat` (`idecomp=2` in `mmpbsa_template.in`), assigns each
   residue row to its subunit (GAP2, PRK, CP12, or NAD) by chain-symmetry block transitions, and
   writes long-format per-residue and per-subunit-summed CSVs plus a text summary.

Steps 5 and 6 are the calculation-side outputs consumed downstream by the analysis scripts
elsewhere in this repo (contact/SASA/convergence/tier-2-dynamics/buffering analyses) — those are
not included in this directory.

## Template files

- **`mmpbsa_template.in`** — The `gmx_MMPBSA` input file: Generalized Born (`igb=8`, `saltcon=0.15`,
  `PBRadii=4`/mbondi3), per-residue decomposition (`idecomp=2`, `dec_verbose=2`, all residues).
  Copied verbatim into each system's `mmgbsa/` working directory as `mmpbsa.in` by both
  `stage_mmgbsa_inputs.py` and `run_mmgbsa.sbatch`.
- **`make_mmpbsa_index.py`** — Generates the `mmpbsa.ndx` GROMACS index file defining the `REC`
  (GAP2+PRK[+NAD]) and `LIG` (CP12) atom groups from a system's `solute_fixed.pdb`, based on chain
  ID.

## Dependencies

- GROMACS 2025.0
- `gmx_MMPBSA` (conda env `gmxMMPBSA`)
- Python 3 with `pandas`

## Notes

- Paths are hardcoded to this project's NERSC Perlmutter scratch layout; reusing these scripts elsewhere requires updating the `ROOT`,
  `ENSEMBLES`/`ENS_BASES`, and `TEMPLATE` path constants at the top of each script.
- `run_mmgbsa.sbatch` reads `ENSEMBLE` (`HM2` or `MED4`) from the environment (set via
  `sbatch --export`, as `submit_mmgbsa.sh` does) and optionally `LIST_OVERRIDE` and `FORCE`.
